# 游戏接口防刷

HTTP 和 WebSocket 的提问、猜测在 GameBusiness 中共用 GameUsageGuard。鉴权、游戏归属、参数、游戏状态及已完成请求的幂等检查先执行；额度与并发预留在调用 Coze 之前执行，并发租约保持到业务保存完成。每个身份和每局游戏最多一个进行中的请求。

Redis Lua 在一次操作中检查并预留全部额度及并发槽。计数使用用户 ID 或匿名会话 ID，不使用 JWT 文本；刷新登录令牌不会重置身份额度。来源 IP 与全站额度覆盖新匿名会话和跨 HTTP/WS 请求。额度超限返回 `request.too_frequent`，并发已满或 Redis 不可用返回 `system.busy`，这些情况下不会调用 Coze。

## 默认预算

| 范围 | 每分钟 | 每日 | 同时进行 |
| --- | ---: | ---: | ---: |
| 匿名会话 | 10 | 120 | 1 |
| 注册用户 | 20 | 300 | 1 |
| 来源 IP | 60 | 1000 | 4 |
| 全站游戏 | — | 10000 | 20 |

预算单位为预留的最大 Coze 请求尝试次数。一项游戏操作按 `1 + COZE_RETRY_TIMES` 预留，成功时也不返还未使用的重试预算；超时及失败也不退回，以防重复消耗。默认一次重试时，一项操作预留 2 单位。每日为 UTC 固定窗口，不是人民币账单硬上限；窗口边界允许相邻窗口的流量。后台内容解析不属于游戏预算，需要单独管控后台权限及供应商费用。

租约过期时间覆盖全部调用超时、重试等待并留出 60 秒余量。正常完成或抛异常后按随机租约 ID 释放；进程崩溃靠到期恢复，不会误删后续请求的租约。额度存放在 Redis，重启/清空 Redis 会丢失预算计数：生产应启用持久化并为供应商配置独立消费告警/限额。请依据调用日志与实际单次费用调整配置。

## 来源 IP 与上线

配置 `TRUSTED_PROXY_CIDRS` 为实际可控网关、NAS 代理的精确 IP 或专用代理网段，不允许使用 `0.0.0.0/0` 或 `::/0`。解析从直接连接端开始，沿 X-Forwarded-For 从右向左跳过可信代理，遇到第一个非可信地址即停止。不要将客户端或不受控容器所在大网段加入信任列表。默认留空不信任转发头，反代后的用户将共用网关 IP 限额，部署时必须按网络拓扑配置以避免误限。

现有网关会追加真实连接地址到转发链；外层反代也必须覆盖/追加真实地址。Webman HTTP/WS 端口应仅对网关开放。修改配置后重启 HTTP 与 WebSocket 进程。

HTTP 入口按可信 IP 限流，匿名会话签发/续期分别最多 5 次/分钟、50 次/日，创建游戏最多 20 次/分钟、500 次/日。所有匹配窗口均检查，任意 Authorization/X-Anonymous-Token 头不会改变计数。WebSocket 每个 IP 最多 180 条消息/分钟，消息最大 16 KiB，连接帧大小限制为 32 KiB，消息频率检查涵盖认证请求；它与游戏业务额度分别限制消息量和付费操作。

## 验证范围

运行 PHPUnit、PHPStan 与代码格式检查；针对令牌变化、伪造代理头、Redis 故障、配额拒绝、回调异常、租约释放、HTTP/WS 共用身份建立回归。

离线 Lua 回归直接提取生产脚本，使用内存 Redis 命令替身验证身份/IP/全站额度、分钟/每日窗口、并发拒绝、过期恢复和租约归属。可执行 `php bin/export-game-usage-lua-test.php > runtime/game-usage-test.lua` 后用 `lua runtime/game-usage-test.lua`（Lua 5.2+）运行；没有 Lua 时可用 `npm exec --yes --package=fengari-node-cli@0.1.0 -- fengari runtime/game-usage-test.lua`。这不创建或连接数据库，也不替代 Redis 集成测试。

上线验收应在明确授权的测试环境验证真实 Redis 下的并发原子性、两个通道混合调用、多个匿名会话共用 IP、重启恢复及反代后的真实 IP。不要在生产发起压测。请求量/额度拒绝率和 Coze 消耗告警应接入现有监控。
