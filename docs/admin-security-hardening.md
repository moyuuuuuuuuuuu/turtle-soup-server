# 管理后台安全修复与上线

本次修改涉及管理前端和服务端，必须配套发布。保留 SaiAdmin 的管理接口响应和权限约定。

## 1. 签名密钥轮换（上线前必须完成）

旧管理 JWT 密钥曾进入 Git，必须视为已泄露。删除当前代码中的值不能撤销 Git 历史中的副本，也不能让部署中的旧令牌失效。

在实际部署环境文件上执行以下脚本，每次会生成两份独立随机密钥，保留其他配置，不输出密钥：

```sh
php bin/rotate-admin-jwt-keys.php /absolute/path/to/production.env
```

配置项为 `ADMIN_JWT_ACCESS_SECRET` 和 `ADMIN_JWT_REFRESH_SECRET`，均为 32 随机字节的 64 位十六进制编码。不同环境必须独立生成。不要复制示例值、旧值或其他业务密钥。环境文件只能由部署用户读取，不能提交仓库。

将环境变量注入所有服务端实例后，重启全部 worker/容器；只更新磁盘文件不会改变已运行进程。Compose 使用 env_file 时需重新创建容器，而非只 restart。所有管理员需要重新登录。启动校验拒绝空值、重复密钥和已泄露密钥。

本次代码修改不代表已操作线上密钥，也不重写 Git 历史。

## 2. 历史敏感日志

新增管理员表单不再提交 `password_confirm`；服务端操作日志与异常上下文递归脱敏密码、令牌、验证码、敏感内容及联系方式，并去掉日志路由中的查询串。

历史数据库、文件日志、反向代理日志和备份不会因代码更新自动清理。需要在确认目标环境并获得数据库操作授权后，分批脱敏 `sa_system_oper_log.request_data` 中的敏感字段和 `router` 查询串；处理异常日志及终端 URL 的访问日志。不得把原始日志内容输出到终端或工单。对可能泄露的管理员密码安排重置，对相关令牌执行撤销/轮换。

查看操作日志的接口也会在响应前脱敏已有记录，降低清理前的进一步暴露风险。

## 3. XSS

插件说明经过 DOMPurify 标签、属性、URL 协议白名单净化。终端输出先进行 HTML 转义，再添加受控 ANSI 颜色标签。测试覆盖事件属性、危险 URL、SVG、嵌套标签以及正常格式保留。

## 4. 退出登录

`POST /core/logout` 撤销当前登录会话。每次登录生成独立随机会话 ID；复制的访问令牌在退出后被拒绝，其他登录不受影响。当前管理前端没有刷新令牌入口；若以后增加刷新接口，必须通过同一会话撤销校验，不能直接调用 Tinywan 刷新后绕过撤销记录。

撤销记录存放在 Redis 的 `admin:revoked-session:*`，不保存原始令牌。Redis 不可用时校验失败关闭；应启用 Redis 持久化并保留这些记录至 TTL 到期，避免删除撤销记录使尚未过期的令牌恢复有效。主动退出在撤销成功后才清空本地状态；网络错误允许重试。

## 5. 终端连接

终端改为带 `Authorization` 请求头的 POST SSE。GET 和只有查询参数令牌的请求被拒绝，普通管理员和已撤销会话被拒绝。服务端验证在创建终端和发送事件流前完成。流中断不会自动重放命令，退出登录会中止前端连接。已开始执行的服务端进程不因浏览器断开而保证终止。

如跨域访问，需在 `CORS_ALLOWED_ORIGINS` 明确配置管理站点；推荐使用同源反向代理。不能回退到 URL 携带令牌。

商店用户信息、已购应用和版本查询也改为 POST，请求体传递商店令牌，避免访问日志记录凭证；服务端只从 POST 数据读取商店令牌。

npx pnpm@9.15.9 build
npx pnpm@9.15.9 audit
